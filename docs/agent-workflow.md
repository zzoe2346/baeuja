# 에이전트 운영 안내

개발 에이전트를 바꿔도 같은 제품 요구사항, 설계와 품질 기준을 사용한다. 공통 지침의 원본은 [AGENTS.md](../AGENTS.md)이며, 도구별 파일은 이 원본에 연결하는 진입점이다.

앱이 교재를 생성할 때는 현재 요구사항대로 Codex CLI를 사용한다. 이 문서는 저장소를 개발하고 유지보수하는 에이전트를 위한 규약이며 생성 서비스를 변경하는 설정이 아니다.

## 도구별 진입점

2026-10-10 공식 문서 확인 기준이다. 설치 버전과 실행 모드에 따라 실제 지침 로딩을 확인한다.

| 개발 도구 | 저장소 진입 파일 | 공통 지침 연결 |
|---|---|---|
| Codex | [AGENTS.md](../AGENTS.md) | 프로젝트 지침으로 읽는다. |
| Claude Code | [CLAUDE.md](../CLAUDE.md) | `@./AGENTS.md` import로 공통 지침을 불러온다. |
| Gemini CLI | [GEMINI.md](../GEMINI.md) | `@./AGENTS.md` import로 공통 지침을 불러온다. |
| Cursor Agent | [AGENTS.md](../AGENTS.md) | 루트 AGENTS.md를 사용한다. 별도 `.cursorrules`를 만들지 않는다. |
| GitHub Copilot | [copilot-instructions.md](../.github/copilot-instructions.md) | 공통 지침을 읽도록 안내한다. AGENTS.md 직접 지원 여부는 IDE와 실행 모드에 따라 다르다. |
| 그 밖의 에이전트 | [AGENTS.md](../AGENTS.md) | 자동 로딩을 지원하지 않으면 파일을 직접 컨텍스트에 제공하거나 읽도록 지시한다. |

Claude와 Gemini의 import는 코드 블록이나 인라인 코드 밖의 독립된 행에 둔다. 일반 Markdown 링크를 import로 간주하지 않는다. Copilot은 파일 읽기가 가능한 모드에서 공통 지침을 읽고 적용하도록 구성했다. 파일 읽기가 없는 채팅 모드까지 자동 적용된다고 가정하지 않는다.

Cursor의 규칙은 Agent 대상이며 Tab 등 모든 AI 기능에 적용되는 것은 아니다. Copilot은 공식 지원 표에서 사용하는 IDE와 기능을 확인한다. 어느 도구든 개인 설정, 상위 디렉터리 지침과 버전 차이가 결과에 영향을 줄 수 있다.

## 시작과 도구 전환

1. 저장소 루트에서 작업을 시작하고 브랜치, Git 상태와 관련 diff를 확인한다.
2. 로딩된 지침 목록과 AGENTS.md의 공통 규칙을 확인한다. 자동 로딩이 없으면 직접 파일을 읽는다.
3. 사용자 요청과 관련된 요구사항, 설계, QA 기록만 읽어 변경 범위와 미완료 항목을 파악한다.
4. 기존 사용자 변경을 보존하며 구현하고, 변경에 맞는 검증을 수행한다.
5. 완료한 범위와 미확인 사항을 기록하고 논리 단위로 커밋한다. 다음 에이전트가 Git과 문서만으로 작업을 이어갈 수 있게 한다.

처음 사용하는 도구에서는 “읽은 지침 파일과 이번 변경에 적용할 규칙을 요약해 줘. 파일은 수정하지 마.”로 확인할 수 있다. Claude Code는 `/context`에서 로딩된 지침을 확인하고 `/memory`에서 관련 파일을 탐색한다. Gemini CLI는 `/memory show`로 합쳐진 컨텍스트를 확인한다. 요약 응답만으로 모든 규칙의 준수를 입증하지는 않으며, 실제 diff와 검사 결과도 확인한다.

다른 에이전트에 넘길 때는 다음 정보를 짧게 남긴다. 새 인계 문서가 꼭 필요한 것은 아니며 작업 결과나 관련 QA 기록에 포함해도 된다.

```text
목적과 승인된 범위:
브랜치와 기준 커밋:
변경 파일과 이유:
검사 명령과 실제 결과:
미확인 항목과 재현 방법:
커밋, 남은 diff와 다음 작업:
```

## 문서 작성 규약

- 공통 행동 규칙은 AGENTS.md에 둔다. 도구별 진입 파일에는 로딩 안내만 두고 공통 규칙을 독립적으로 유지하지 않는다.
- 제품 결정은 [요구사항](requirements.md), 책임과 데이터 계약은 [상세설계](lld.md), 완료 조건은 [품질 기준](quality.md)에 쓴다. 실제 수행 결과는 [QA 기록](qa.md)에 남긴다.
- UI와 OS 대응은 [디자인 기준](design.md)과 [호환성 안내](compatibility.md)를 갱신한다. 현재 공식 출처와 확인 날짜를 남기며 특정 SDK 이름만으로 최신 디자인을 주장하지 않는다.
- UTF-8 Markdown과 저장소 기준 상대 경로를 사용한다. 개인 홈 경로, 대화 ID, 도구 내부 메모리 경로를 공통 규칙의 필수 의존성으로 만들지 않는다.
- 지침은 짧고 확인 가능한 행동과 명령으로 쓴다. 상세 설명과 과거 검증 결과를 진입 파일에 계속 쌓지 않는다. 글쓰기 방식은 AGENTS.md를 따른다.
- 규칙을 바꿀 때 관련 문서의 충돌과 링크를 함께 확인한다. `scripts/project-check.swift`가 루트, docs와 .github의 Markdown 링크 및 진입 파일의 독립된 상대 import 경로를 검사한다.
- 하위 디렉터리 지침은 실제로 다른 규칙이 필요한 경우에만 추가한다. 도구마다 하위 지침 발견 방식이 다르므로 자동 로딩을 확인하거나 적용 파일을 명시한다.
- 특정 도구의 플러그인, MCP나 개인 스킬 설치를 공통 작업의 전제로 만들지 않는다. 필요한 도구가 없으면 사용할 수 있는 방식과 검증의 한계를 기록한다. 권한과 인증, 글로벌 설정은 도구 교체를 위해 자동 변경하지 않는다.

## 검증과 완료 기준

| 변경 | 수행할 검증 |
|---|---|
| 문서와 진입 파일 | 요구사항 충돌, 상대 링크, import 대상, `git diff --check`와 지침 로딩 확인. 로딩을 실제 실행하지 않았으면 그렇게 기록한다. |
| Swift 코드와 검사 도구 | `./scripts/check.sh` 및 변경한 동작의 검사. |
| UI | 위 검사와 실제 앱 실행, 화면 경계와 읽기 흐름 확인. 화면이 바뀌면 README 캡처와 출처 기록을 갱신한다. |
| 생성, 저장과 PDF | 실제 교재와 시각자료 일치, 퀴즈, 저장 후 재개 및 PDF를 검토한다. 재사용할 수 있는 자료와 실제 새 호출을 구분한다. |
| 성능 | 같은 재현 조건에서 전후 근거를 기록한다. 합성 입력과 실제 스크롤 지연을 구분한다. |

문서 변경 때문에 실제 생성이나 UI 검증을 새로 수행한 것처럼 기록하지 않는다. 실행하지 못한 도구, OS와 기능은 미확인으로 남긴다. 지침 로딩은 안내를 제공하는 방식이며 실행 권한을 부여하거나 검사를 대체하지 않는다.

## 커밋 기여 표기

사용자 Git author를 유지한다. 한국어 Conventional Commits와 작업 단위는 AGENTS.md를 따른다.

Codex가 기여한 커밋은 기존에 사용자가 정한 관례대로 메시지 끝에 빈 줄과 다음 트레일러를 둔다.

```text
Co-authored-by: Codex <noreply@openai.com>
```

이 이름과 이메일은 저장소의 협업 관례이며 OpenAI 공식 기본값이나 검증된 GitHub 프로필 주소로 주장하지 않는다. Claude나 다른 에이전트는 이 표기를 재사용하지 않는다. 해당 도구의 기여 표기는 사용자 또는 도구 설정에 정해진 값을 사용하고, 정해진 값이 없으면 임의의 공동 작성자 트레일러를 추가하지 않는다.

## 공식 근거와 갱신

도구 업데이트로 지침 파일의 이름, import 또는 지원 모드가 달라지면 공식 문서를 다시 확인하고 진입 파일과 위 표를 함께 갱신한다. 전역 설정을 바꿔 호환성을 강제하지 않는다.

- [OpenAI: AGENTS.md 지침 탐색](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- [Anthropic: CLAUDE.md와 import, 로딩 확인](https://code.claude.com/docs/en/memory)
- [Google: GEMINI.md와 import](https://geminicli.com/docs/cli/gemini-md/)
- [Cursor: AGENTS.md와 규칙 적용 범위](https://cursor.com/docs/rules)
- [GitHub: 실행 환경별 custom instructions 지원](https://docs.github.com/en/copilot/reference/custom-instructions-support)
