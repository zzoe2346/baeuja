# 001: AI 유지보수를 위한 작은 경계와 공통 검사

상태: 승인·적용. 날짜: 2026-10-08. 사용자는 이름 변경을 보류하고 문서·린트·CI·구조 정리를 진행하도록 승인했다.

## 맥락

앱은 다양한 주제의 계획·교재를 생성하고 로컬에 보관한다. 화면·생성 결과·스크롤 문제는 컴파일 성공만으로 발견되지 않았다. 다음 에이전트도 공식 디자인 확인, 실제 흐름, 성능 증거와 저장 계약을 이어받아야 한다.

## 결정

- 기존 SPM 타깃은 유지하며 Core의 Domain/Application/Infrastructure와 UI의 기능별 파일로 책임을 나눈다. 화면은 입력·표시, Store는 상태·명령 연결, LessonPreparation은 자료 준비·실패 정리, 인프라는 CLI·저장·렌더링·PDF를 담당한다.
- Domain에는 Foundation 기반 값·검증만 둔다. UI 프레임워크 import를 자동 검사한다. 파일 검사보다 강한 컴파일 경계가 필요해질 때 새 타깃으로 분리한다.
- 일반화한 repository/coordinator 프로토콜을 모든 타입에 추가하지 않는다. 실패·취소·채택을 의미 있게 검증할 자료 렌더링 경계에만 주입 지점을 둔다.
- 포맷은 swift-format, 추가 린트는 고정 SwiftLint의 작은 correctness 규칙으로 시작한다. 동일한 check 명령을 로컬과 CI에서 실행한다.
- 실제 AI 생성·화면·성능 QA는 위험에 따라 추가하고 출처·검증 한계를 기록한다. CI는 인증 없이 샘플만 검증한다.
- 앱·저장소 이름, bundle identifier, 저장 경로, 최소 지원 OS와 언어 모드는 유지한다.

## 결과와 다음 조건

큰 프레임워크·런타임 의존성 없이 분리된 책임과 실행 가능한 검사를 얻는다. 타깃 간 Domain 격리는 아직 컴파일러로 강제하지 않는다. Swift 6 전환, 비동기 저장·PDF 연산 분리, 실제 스크롤 trace baseline은 각각 증거와 회귀 검증을 갖춘 후속 변경으로 진행한다. 이 결정의 변경은 이유·영향·검증을 새 결정 기록에 남긴다.
